# Test Purposes

Run `python3 -m unittest discover -s tests` from the repository root. These tests
use small deterministic/synthetic fixtures, not the formal simulation campaigns.
Python dependencies and Node.js are required for the complete retained suite.

| Test file | Purpose |
| --- | --- |
| `test_tutoring_design_validation.py` | Capped task validation, discrete Bayes/likelihood identities, sampling and terminal decisions, budget/cap invariants. |
| `test_tutoring_design_revision.py` | Frozen baseline/engine hashes, single permitted C3 change, selection criteria and isolated runner imports. |
| `test_allocation_identifiability.py` | C2 response-rule definitions, synthetic group/individual recovery and unsupported-recipe refusal. |
| `test_tutoring_model_bridge.py` | Independent finite-prior moments, affine GPA identity and model-isolation checks. |
| `test_tutoring_inference.py` | Participant-level endpoints, directional Student/Welch contrasts, multiplicity and unavailable cases. |
| `test_tutoring_calibration.py` | Fixed configuration identity, generators, scalar/vector parity, checkpoint/resume and mismatch refusal. |
| `test_tutoring_planning.py` | Covariance checks, analytic power, conditional sample-size calculations and 28-scenario mapping. |
| `test_tutoring_bounded_inference.py` | Geometry/support checks, bounded estimators, selection assumptions and unavailable endpoints. |
| `test_tutoring_bounded_robustness.py` | Frozen bounded generators, parity, aggregate denominators and diagnostic criteria. |
| `test_tutoring_empirical_bernstein.py` | Variance-adaptive bounds, eligible-slope support and finite-cohort partial identification. |
| `test_tutoring_identifiability_robustness.py` | Source-generated schedule support, C1 ambiguity, attainable bounds and selection diagnostics. |
| `test_tutoring_reproduction.py` | Source-to-output small fixtures, public CLI, failure readback, output protection and conditional planning. |
| `test_capped_publication.py` | Branch reproduction scope, capped scientific settings, install-first/default-off notebook structure and exclusion of incompatible workflows. |

Passing software tests does not establish human validity, universal Type-I
control or globally optimal metalevel decisions. Formal results retain their
original populations and uncertainty statements.
